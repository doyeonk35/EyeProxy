# Prog 호스트 그룹 탭·탭 복원·기기 이름·Android 안내·SSL 묶음 설계

> 사용자 지시: 질문 없이 진행하고, Proxyman에 같은 기능이 있으면 그것을 참고한다. Proxyman 자료로 확인하지 못해 내가 정한 부분은 **(내 판단)**으로 표시했다.

## 1. 왜

- **호스트 그룹 탭.** 지난 묶음에서 탭은 생겼지만 탭 하나는 사이드바 항목 하나(도메인 하나, 앱 하나, 기기 하나)만 본다. 우리 앱은 API, 인증, 이미지, 재생, 광고, 로그 서버처럼 도메인이 여러 개다. 그래서 "우리 앱 도메인 전부"를 한 탭에서 보려면 필터 막대 규칙을 손으로 짜야 한다. 지난 핸드오버도 이것을 다음 묶음으로 남겼다.
- **탭 복원.** 다시 실행하면 라이브 탭 하나만 열린다. 매일 같은 탭 구성(전체, TV 한 대, 우리 도메인 묶음)을 다시 만들어야 한다.
- **기기 이름.**
  - 직접 붙인 이름이 IP에 묶여 있다. 공유기가 IP를 바꾸면 이름이 옛 IP에 남고, 새 IP의 기기에는 다시 붙여야 한다.
  - Mac 자신이 LAN IP로 보낸 트래픽은 "Remote devices"에 IP로만 보인다.
  - 기기 종류에 Android가 없다. 그래서 Google TV도 "알 수 없음"으로 보인다.
- **Android 인증서 안내.** 실제로 Chromecast with Google TV에 앱 트래픽을 붙여 본 기록(레포 밖 메모)에 따르면, 지금 안내대로 하면 막힌다.
  - TV에서 "기기에 CA 설치" 단계부터 실패한다. 설치 인텐트로 열면 "인증서 파일을 읽을 수 없음"이 뜬다.
  - CA를 설치해도 앱이 믿지 않는다. 앱은 스플래시에서 `Trust anchor for certification path not found`로 멈춘다.
  - 통한 방법은 하나였다. 디버그 빌드의 `network_security_config`에 Prog CA를 `@raw`로 넣는 것이다.
- **SSL Proxying 묶음.** 팀원마다 SSL Proxying List를 손으로 채운다. 한 사람이 정리한 도메인 목록을 받아 한 번에 켜고, 내 목록을 내보내 넘길 방법이 없다.

## 2. 근거: Proxyman에서 확인한 것

- **6.3 메뉴(지난 묶음에서 접근성 API로 읽음).** File 메뉴에 `New Domain or App ⇧⌘K`와 `New Folder`가 있다. 무엇을 하는지는 문서에 없다.
- **Multiple Tabs 문서.**
  - 탭마다 출처(앱·도메인) 하나, 필터, 선택한 요청이 따로 있다.
  - 새 탭을 여는 방법은 ⌘T, 탭 막대의 `+`, 사이드바 우클릭 Open as New Tab이다.
  - 탭 하나에 여러 도메인이나 앱을 묶는지, 다시 실행할 때 복원하는지는 적혀 있지 않다.
- **SSL Proxying 문서.**
  - Include List와 Exclude List가 있다. 항목은 앱, 도메인, 와일드카드다.
  - 와일드카드는 `*`(전부), `*.domain.com`, `v?.domain.com`(`?`는 한 글자)을 쓴다.
  - 사이드바나 요청을 우클릭하면 Enable SSL Proxying이 나온다.
- **설정 가져오기·내보내기 문서.**
  - 한 도구의 규칙을 골라 우클릭 ▸ Export Settings…로 내보낸다.
  - 전체 백업은 `.config` 파일이고, Override 또는 Append로 가져온다.
  - CLI는 SSL Proxying List를 포함한 규칙을 JSON으로 내보낸다.
  - 이미 있는 Proxyman 가져오기(`ProxymanImporter`)가 읽는 SSL 목록 모양은 `{"nodes":[{"kind":{"domain":[{"url":…}]}}]}`다.
- **확인하지 못한 것.**
  - `New Domain or App`의 정확한 동작
  - 탭 복원 여부
  - 원격 기기를 MAC으로 알아보는지
  - SSL 목록 하나만 평문으로 주고받는 형식

## 3. 목표·비목표·반목표

**목표**

- **호스트 그룹 탭.** 도메인 패턴(와일드카드)과 이 Mac 앱을 묶은 "호스트 그룹"을 만들어 탭 하나로 본다. File ▸ New Domain or App ⇧⌘K로 만들고, 사이드바 Favorites ▸ Groups에 저장한다.
- **탭 복원.** 종료할 때 열려 있던 탭(라이브와 파일, 사이드바 선택, 필터 규칙, 앞 탭)을 다음 실행 때 다시 연다.
- **기기 이름 개선.**
  - 같은 네트워크 기기는 ARP 표의 MAC으로 알아본다. IP가 바뀌어도 직접 붙인 이름과 종류가 따라간다.
  - Mac 자신의 LAN IP는 이 Mac의 컴퓨터 이름(Bonjour 이름)으로 보인다.
  - 기기 종류에 Android TV, Google TV, Android 폰을 넣는다. Google Cast 광고로 TV 종류를 채운다.
- **Android 안내.** Android TV·Google TV 안내를 "기기에 CA 설치"에서 "디버그 빌드에 CA 넣기"로 바꾼다. XML, CA 복사, 지문 확인, adb 프록시 설정과 해제, 진단 문구를 준다.
- **SSL 묶음.**
  - 호스트 목록 파일(평문)을 가져와 SSL Proxying List에 한 번에 넣는다. 그룹으로도 저장할 수 있다.
  - 지금 목록이나 그룹을 같은 형식으로 내보낸다.
  - 사이드바 기기·앱 우클릭으로 "그 기기나 앱의 모든 도메인"을 한 번에 켠다.

**비목표(이번에 하지 않음)**

- Proxyman `New Folder`. 사이드바 폴더와 그룹의 중첩.
- 그룹에 원격 기기를 넣는 것. 기기와 도메인을 함께 거르려면 그룹 탭에서 필터 막대의 Client·IP 규칙을 쓴다.
- SSL Proxying Exclude List, 항목별 켜기·끄기, 앱 단위 SSL 항목.
- 가져온 목록 단위로 한 번에 빼기("이 파일의 호스트 지우기"). 지금처럼 목록에서 하나씩 지운다.
- Charles 형식 가져오기, URL에서 목록 받아 오기, 목록 자동 동기화.
- Android 폰 종류 자동 판별. 폰은 Cast 광고를 내지 않으므로 종류는 직접 고른다.
- adb로 CA를 시스템 저장소에 넣는 것(루트 필요). 기기 식별에 adb나 `arp` 실행 쓰기.
- 여러 창(Move Tab to New Window)의 배치까지 그대로 복원하는 것. 복원은 한 창에 모은다.

**반목표(이렇게 되면 실패)**

- 사용자의 릴리스 앱이 같은 `devices.json`을 읽다가 손상으로 판정해 옆으로 치운다. 새 종류 값이 `kind`에 그대로 쓰이면 이렇게 된다.
- MAC 처리 중에 직접 붙인 이름이 사라지거나, 다른 기기로 옮겨 붙는다.
- 그룹 탭 때문에 트래픽이 많을 때 목록 계산이 눈에 띄게 느려진다. 요청마다 정규식을 다시 만들면 이렇게 된다.
- 가져온 파일이 확인 없이 SSL 목록을 바꾼다. `*` 하나로 모든 HTTPS가 복호화되는데도 알리지 않는다.
- 커밋한 파일(코드, 테스트, 문서, 예시 목록)에 회사 도메인, 실제 기기 IP, 기기 코드명이 들어간다.
- 복원하다가 사라진 파일 때문에 오류 알림이 줄줄이 뜨거나 빈 탭이 남는다.
- 이 Mac 이름을 붙이려고 Bonjour 찾기를 시작해서, 이 Mac 트래픽만 보는 사용자에게 로컬 네트워크 권한 창이 뜬다.

## 4. 동작

### 4.1 호스트 그룹과 그룹 탭

- **호스트 그룹 = 이름 + 도메인 패턴 목록 + 앱 목록.** 앱은 이 Mac 프로세스(`ProcessIdentity.groupKey`)다.
  - 요청이 그룹에 맞는 조건: 호스트가 패턴 중 하나에 맞거나, 귀속된 앱이 목록에 있다(OR).
  - 원격 기기의 요청은 귀속 앱이 없으므로 도메인으로만 맞는다.
- **패턴 문법은 SSL Proxying List와 같다.**
  - `*`는 임의 문자열, `?`는 한 글자이고 대소문자를 무시한다. 예: `api.example.com`, `*.example.com`, `v?.example.net`.
  - 지금 SSL 매칭에는 `?`가 없으므로 이번에 넣는다. Proxyman 목록을 가져왔을 때 같은 뜻이 되게 하려는 것이다. **(내 판단)**
- **그룹은 사이드바 선택의 한 종류다(`SidebarItem.group`).** Proxyman 문서대로 "탭마다 출처 하나"를 따른 것이다. **(내 판단)**
  - 그룹을 고른 탭은 그룹에 맞는 요청만 보인다.
  - 같은 탭에서 사이드바의 다른 항목을 누르면 출처가 그 항목으로 바뀐다. Proxyman 탭과 같다.
- **File ▸ New Domain or App… ⇧⌘K.** 앞 탭 창에 시트를 띄운다. 동작은 문서에 없어 **(내 판단)**으로 정했다.
  - **이름:** 비우면 첫 항목 이름에 "외 N"을 붙인다.
  - **도메인 패턴:** 여러 줄 입력이다. 줄이나 쉼표로 나눈다. URL을 붙여 넣으면 호스트만 쓴다.
  - **고르기 목록:** 이 탭 세션의 도메인과 앱을 검색칸과 체크로 고른다.
  - **가져오기… 버튼:** 호스트 목록 파일(§4.5)로 도메인 칸을 채운다.
  - **"Favorites에 저장"(기본 켬):** 끄면 이 탭에서만 쓰고 저장하지 않는다.
  - **Open:** 앞 탭과 같은 세션을 보는 새 탭을 열고 그 그룹을 고른 상태로 둔다. 앞 탭이 라이브면 라이브 탭, 파일 탭이면 같은 파일을 본다. Open as New Tab과 같은 규칙이다. 항목이 하나도 없으면 비활성이다.
  - **미리 채우기:** 시트를 열 때 앞 탭의 사이드바 선택이 도메인이나 경로면 그 호스트를, 앱이면 그 앱을 미리 채운다.
- **사이드바 Favorites ▸ Groups.** Pinned 아래에 저장한 그룹이 놓인다. 배지는 그룹에 맞는 요청 수다.
  - **우클릭 메뉴:**
    - Open as New Tab
    - Edit…: 같은 시트로 고친다. 저장하면 같은 id의 그룹을 바꾼다.
    - Enable SSL Proxying: 그룹의 도메인 패턴을 SSL 목록에 더한다.
    - Export…: §4.5 형식으로 저장한다.
    - Delete: 확인 없이 지운다. 이미 그 그룹을 보고 있는 탭은 계속 그 그룹을 본다.
  - **그룹이 없을 때:** "⇧⌘K로 그룹 만들기"라는 안내 글자를 보인다.
- **탭 제목:** 그룹 이름.
- **저장 위치:** `AppSettings.hostGroups`(UserDefaults)다. 저장 순서가 사이드바 순서다.

### 4.2 탭 복원

- **설정 General ▸ "Restore Tabs at Launch"(기본 켬).** **(내 판단)**
- **언제 저장하나.** 종료가 확정될 때(종료 확인 알림을 통과한 뒤) 한 번 저장한다.
  - 크래시나 강제 종료 때는 저장하지 않는다. 그러면 그 전 저장본이 남는다.
  - 창을 모두 닫고 종료하면 "탭 없음"이 저장되고, 다음 실행은 라이브 탭 하나로 시작한다.
- **무엇을 저장하나.** 탭마다 다음 네 가지를 저장한다.
  - 종류: 라이브인지, 파일이면 경로
  - 사이드바 선택: 그룹은 그룹 정의를 통째로 넣는다. 그래서 저장한 그룹을 지워도 복원된다.
  - 필터 규칙과 AND/OR
  - 앞 탭이 몇 번째인지

  칩, 숨김 포함, 정렬, 선택, 펼친 도메인은 저장하지 않는다. 지금도 저장하는 것은 규칙뿐이다. **(내 판단)**
- **탭 순서.** 앞 창의 탭 막대 순서를 따르고, 다른 창의 탭은 그 뒤에 붙인다. 복원하면 모두 한 창에 모인다.
- **복원 순서.**
  - 첫 창은 언제나 라이브 탭(`mainTab`)이다. 저장본의 첫 라이브 탭 상태가 여기에 들어간다. 저장본에 라이브 탭이 없으면 빈 라이브 탭이다. **(내 판단)**
  - 나머지는 저장 순서대로 뒤에 붙인다. 파일 탭이 맨 앞이었더라도 라이브 탭 뒤로 간다.
- **필터 규칙 저장 담당.** 규칙을 `settings.filterRules`에 계속 쓰는 탭은 지금처럼 `mainTab` 하나다. 다른 탭의 규칙은 복원 저장본에만 남는다.
- **파일 탭.** 파일을 다시 읽어 연다. 파일 탭에서 한 Clear·Delete는 복원되지 않는다. 지금도 저장하지 않고 닫는 동작이다.
  - 파일이 없거나 읽지 못하면 그 탭만 조용히 건너뛴다. 알림을 띄우지 않고 Open Recent 목록도 건드리지 않는다. **(내 판단)**
- **파일 더블클릭으로 실행해도** 복원은 그대로 하고, 연 파일은 그 뒤에 새 탭으로 붙는다.

### 4.3 기기 이름

#### 4.3.1 MAC으로 알아보기 (평가 결과: 넣는다, 한계 있음)

- **방법.** 시스템 API `sysctl(CTL_NET, PF_ROUTE, 0, AF_INET, NET_RT_FLAGS, RTF_LLINFO)`로 ARP 표를 읽는다. `arp -a`가 쓰는 것과 같은 표다. 이렇게 하면:
  - 외부 도구를 실행하지 않는다.
  - 루트 권한도 로컬 네트워크 권한도 필요 없다.
- **되는 경우.** 기기가 Mac과 같은 L2 네트워크(같은 Wi-Fi나 유선)에 있으면, 프록시로 TCP를 연 순간 ARP 표에 그 IP의 MAC이 있다.
- **한계.** 아래 경우에는 지금처럼 IP로만 알아본다.
  - **다른 서브넷:** 공유기나 VPN 너머의 기기는 그 IP의 ARP 항목이 없다. 게이트웨이 MAC과 헷갈리지는 않는다. 정확히 그 IP 항목만 보기 때문이다.
  - **임의 MAC(프라이빗 Wi-Fi 주소):** iOS 14+, Android 10+, Google TV는 기본으로 네트워크마다 고정된 임의 MAC을 쓴다. 같은 Wi-Fi에서는 바뀌지 않으므로 이 기능의 목적(같은 망에서 DHCP가 바꾼 IP)에는 충분하다. 단, "주기적으로 바뀌는" 설정(iOS 18 회전 주소, Android 비영구 임의화)이면 MAC이 바뀔 때 새 기기로 보인다.
  - **IPv6:** 대상이 아니다. 기기 주소는 지금도 IPv4만 맞춘다.
- **언제 읽나.** 루프백이 아닌 주소의 요청이 올 때 읽는다. 같은 주소는 60초에 한 번만 읽는다. **(내 판단)**
- **맞추는 규칙.** 기록은 지우지 않고, 주소마다 가장 최근 기록이 그 주소를 대표한다. **(내 판단)**

  | 상황 | 처리 |
  |---|---|
  | 그 주소의 최근 기록 MAC이 같다 | 그대로 둔다 |
  | 그 주소의 기록에 MAC이 없다(옛 기록), 같은 MAC을 가진 다른 기록이 없다 | 그 기록에 MAC을 적는다 |
  | 같은 MAC의 기록이 다른 주소에 있다(DHCP가 IP를 바꿈) | 그 기록을 새 주소로 옮긴다. 이름, 종류, 자동 이름, 개수가 따라온다 |
  | 그 주소의 기록 MAC이 다르고, 같은 MAC의 기록이 없다(IP를 다른 기기가 받음) | 새 기록을 만든다. 옛 기록은 이름과 MAC을 그대로 갖고 "이전" 기록으로 남는다 |

  - "이전" 기록은 그 기기가 다시 나타나면(MAC이 같으면) 그 주소로 옮겨 가 이름이 되살아난다.
  - 한 주소에 기록이 둘 이상이면 가장 최근(`lastSeen`) 기록의 이름을 쓴다. 대상은 사이드바, Client 열, Export다.
  - 기록 id는 `mac ?? address`다. 같은 주소의 기록이 둘이어도 id가 겹치지 않는다.
- **설정 ▸ 연결된 기기 행.** 주소 옆에 MAC을 보인다. 그 주소를 대표하지 않는 기록에는 "이전" 표시를 단다. 이름 바꾸기는 기록 id로 한다.

#### 4.3.2 이 Mac의 LAN IP

- **이름과 종류.** 루프백이 아닌 요청의 주소가 이 Mac의 LAN 주소(`lanAddresses`)면, 그 기록에 다음을 넣는다.
  - 종류: `.thisMac`. 종류가 "알 수 없음"일 때만 넣는다.
  - 자동 이름: 이 Mac의 컴퓨터 이름(`SCDynamicStoreCopyComputerName`).
- **왜 Bonjour를 쓰지 않나.** Bonjour가 광고하는 이름이 바로 이 컴퓨터 이름이다. 그래서 Bonjour를 쓰지 않고 시스템에서 바로 읽는다. 이러면 권한 창이 뜰 일이 없다. **(내 판단)**
- **우선순위.** 지금과 같이 직접 이름 > 자동 이름 > "이 Mac"·IP다. 루프백 기록은 지금처럼 "이 Mac"이다.

#### 4.3.3 Android 종류

- **새 종류.** `androidTV`(Android TV), `googleTV`(Google TV), `androidPhone`(Android 폰). 설정의 종류 고르기에 나오고, 사이드바 아이콘도 생긴다.
- **Google Cast 광고(`_googlecast._tcp`) TXT `md`(모델 이름)로 종류를 정한다.** **(내 판단)** 이름은 지금처럼 `fn`에서 읽는다.
  - `md`에 "Google TV"가 있거나 `md`가 "Chromecast"로 시작하면 `googleTV`다. 앱을 돌리며 프록시 트래픽을 내는 Chromecast는 Google TV 모델뿐이다.
  - 그 밖의 `md`는 `androidTV`다. 단, "Google Home", "Google Nest", "Nest"로 시작하면 종류를 비운다(스피커·디스플레이).
  - 자동 종류는 지금처럼 종류가 "알 수 없음"일 때만 채운다.
- **`devices.json` 하위 호환(필수).**
  - 사용자의 릴리스 앱(옛 코드)이 같은 파일을 읽는다. 옛 코드는 모르는 `kind` 값을 만나면 파일 전체를 손상으로 보고 옆으로 치운다.
  - 그래서 새 종류는 `kind`에 `"unknown"`으로 쓰고, 실제 값은 새 키 `extendedKind`에 쓴다.
  - 읽을 때는 `extendedKind`를 먼저 보고, `kind`의 모르는 값은 "알 수 없음"으로 읽는다. 앞으로 생길 값에도 안전하다.
  - `mac`도 새 키다. 옛 앱이 이 파일을 다시 저장하면 `mac`과 `extendedKind`가 빠진다. 그러면 MAC은 다시 배우고, 직접 고른 Android 종류는 "알 수 없음"이 된다. 이 손실은 받아들인다.

### 4.4 Android 인증서 안내

Certificate 창 ▸ Android 섹션을 고친다. 탭은 세 개 그대로 둔다(실기기 / 에뮬레이터 / Android TV). TV 탭 이름은 "Android TV·Google TV"로 바꾼다.

- **모든 탭 아래: "디버그 빌드에 CA 넣기" 절.** 지금의 "주의" 절을 바꾼다.
  - **원리.**
    - Android 7 이상 앱은 사용자 CA를 믿지 않는다. 앱의 `network_security_config`가 허용해야 한다.
    - 스토어(release) 빌드는 볼 수 없다. 디버그 빌드가 필요하다.
    - 스토어 앱이 깔려 있으면 서명이 달라 디버그 APK를 덮어 깔 수 없다(`INSTALL_FAILED_UPDATE_INCOMPATIBLE`). 스토어 앱을 지우면 로그인 데이터도 지워진다.
  - **Prog CA SHA-256 지문.** 복사 버튼을 단다.
  - **CA 복사.**
    - "CA를 proxy_ca.crt로 저장…" 버튼: 실행 중인 CA의 PEM을 저장한다.
    - 복사용 명령: `mkdir -p app/src/debug/res/raw && cp "<Prog CA 경로>/ca.pem" app/src/debug/res/raw/proxy_ca.crt`. CA 경로는 실행 때 `AppModel.caDirectory`로 채운다.
  - **XML 두 개(각각 복사 버튼).**
    - `app/src/debug/res/xml/network_security_config.xml`: system·user·`@raw/proxy_ca`를 믿는다.
    - `app/src/debug/AndroidManifest.xml`의 `android:networkSecurityConfig`. main 매니페스트에 이미 있으면 `tools:replace`를 쓰라고 적는다.
  - **확인.** 다음 명령으로 프로젝트에 넣은 파일과 위 지문을 비교한다.

    ```
    openssl x509 -in app/src/debug/res/raw/proxy_ca.crt -noout -fingerprint -sha256
    ```
  - **주의.**
    - CA는 Mac마다 다르므로 커밋하지 않는다(`.git/info/exclude`).
    - Prog CA를 초기화(Reset)하면 다시 복사하고 다시 빌드한다.
  - **진단.**
    - logcat에 `Trust anchor for certification path not found`가 보이면 앱이 CA를 믿지 않는 것이다. 이때 앱은 스플래시에서 멈출 수 있다.
    - 명령 `adb logcat | grep -i "trust anchor"`를 복사 버튼과 함께 둔다.
- **Android TV·Google TV 탭.**
  1. 개발자 옵션 ▸ 네트워크(무선) 디버깅을 켜고 `adb connect <TV IP>:<포트>`로 붙는다. 네트워크 디버깅은 5555, 무선 디버깅은 화면에 보이는 포트다.
  2. **CA는 TV에 설치하지 않는다.**
     - Android 11+는 CA를 설정 화면에서만 설치할 수 있다.
     - Google TV에는 그 화면도 파일 선택기도 없다.
     - 그러니 아래 "디버그 빌드에 CA 넣기"로 간다.
  3. 프록시를 설정한다: `adb shell settings put global http_proxy <Mac IP>:<포트>`.
  4. 디버그 빌드를 실행해 Prog에 요청이 보이는지 본다.
  5. **끝나면 해제한다:** `adb shell settings put global http_proxy :0`.
     - **경고(주황):** 켜 둔 채면 Prog를 끈 뒤 TV의 모든 네트워크가 끊긴다. Prog가 켜져 있어도 다른 앱의 HTTPS가 실패할 수 있다.
  - **버튼(adb가 있을 때):** `adb connect`, `adb로 프록시 설정`, `adb로 프록시 해제`.
  - **뺀다:** 이 탭의 CA push와 "인증서 설치 화면 열기"는 Google TV와 Android 11+에서 실패하므로 뺀다.
  - **adb가 없을 때:** 복사용 명령은 connect와 프록시 설정 두 줄과, 해제 한 줄이다.
  - TV IP 입력칸의 예시는 `192.0.2.10`으로 바꾼다.
- **실기기 탭.** 지금 단계에 한 줄을 더한다: "Android 11+는 내려받은 파일을 눌러서는 설치되지 않는다. 설정 ▸ 보안 ▸ 암호화 및 사용자 인증 정보 ▸ 인증서 설치에서만 된다."
- **에뮬레이터 탭.** 그대로 두고, 아래 절의 번들 방법도 된다고 한 줄 적는다.

### 4.5 호스트 목록 파일과 SSL 묶음

- **형식(내 판단): UTF-8 평문, 한 줄에 패턴 하나.**

  ```
  # Prog host list — 한 줄에 호스트 패턴 하나. *는 임의 문자열, ?는 한 글자.
  api.example.com
  *.example.com
  v?.example.net
  ```

  - 앞뒤 공백은 지운다. 빈 줄과 `#`로 시작하는 줄은 무시한다. CRLF와 BOM도 읽는다.
  - `://`가 있는 줄은 URL로 보고 호스트만 쓴다. 끝의 `:포트`는 뗀다. 소문자로 바꾼다.
  - 허용 글자는 `a-z 0-9 . - _ * ?`다. 그 밖의 글자가 있는 줄은 버리고 개수만 센다.
  - 대소문자를 무시하고 중복을 빼되, 처음 나온 순서는 지킨다.
  - 1 MB보다 큰 파일은 읽지 않는다.
  - 파일 이름(확장자 뺀 것)이 그룹 이름이 된다.
  - 첫 글자가 `{`면 Proxyman SSL 목록 JSON(`{"nodes":[…]}`)으로 읽는다. 이미 있는 Proxyman 가져오기 해석을 그대로 쓴다. Proxyman에서 그 목록만 내보내 받은 경우를 위한 것이다.
- **왜 이 형식인가.**
  - 메신저에 붙여 넣거나 손으로 고칠 수 있다.
  - 주석으로 출처를 적을 수 있다.
  - 팀 공용 목록(예: TVING 도메인 묶음)은 이 형식의 파일을 레포 밖에서 주고받는다. **레포에는 회사 목록을 넣지 않는다.**
- **가져오기.**
  - 위치: 설정 ▸ SSL Proxying ▸ "가져오기…"(`.txt`, `.json`, `.config`).
  - 확인 알림이 뜬다:
    - "패턴 N개(새로 M개)를 SSL Proxying List에 더할까요?"
    - 버린 줄이 있으면 그 개수를 보인다.
    - `*`가 있으면 "모든 HTTPS를 복호화합니다"를 경고 문구로 넣는다.
    - "호스트 그룹으로도 저장"(체크박스, 기본 켬)
  - 확인하면 기존 목록 뒤에 새 패턴만 붙인다(Append). SSL Proxying을 켜고 서버에 적용한다. Override는 두지 않는다. **(내 판단)**
- **내보내기.**
  - 설정 ▸ SSL Proxying ▸ "내보내기…"는 지금 목록 전체를 위 형식(머리 주석 한 줄)으로 저장한다. 기본 이름은 `ssl-proxying-list.txt`다.
  - 그룹 우클릭 Export…는 그 그룹의 도메인 패턴을 `<그룹 이름>.txt`로 저장한다. 앱 항목은 파일에 넣지 않는다. 앱 키는 Mac마다 다를 수 있다. **(내 판단)**
- **한 번에 켜기.**
  - 사이드바 Remote devices의 기기 우클릭 ▸ "Enable SSL Proxying for All Domains": 이 탭 세션에서 그 기기가 쓴 모든 호스트를 더한다.
  - 사이드바 앱 우클릭 ▸ 같은 메뉴: 이 탭 세션에서 그 앱이 쓴 모든 호스트를 더한다. 지금 HTTPS Response 안내의 "Enable all domains"와 같은 함수를 쓴다.
  - 그룹 우클릭 ▸ Enable SSL Proxying.
  - 목록 합치기는 하나의 함수가 맡는다. 대소문자를 무시하고 중복을 빼며, SSL을 켜고 적용한다.

## 5. 제약

- **프로젝트 규칙**
  - 외부 패키지는 허용 목록에 있는 것만 쓴다. `SystemConfiguration`, `Darwin`, `Network`는 시스템 프레임워크라 괜찮다.
  - 모듈 방향은 앱 → Kit → Core다.
  - App Sandbox는 끈다.
  - 커밋 메시지는 `<type>(<scope>): <한국어 요약>`이다.
- **공개 레포**
  - 커밋할 파일에 회사 도메인, 사내 호스트 목록, 로컬 경로, 실제 기기 IP·MAC·코드명을 넣지 않는다.
  - 예시는 `example.com`·`example.net`, `192.0.2.x`, `00:00:5e:00:53:xx`(문서용 MAC), 지어낸 이름만 쓴다.
- **공유 데이터.** Debug 앱과 사용자의 릴리스 앱은 `~/Library/Application Support/com.tv.eyeproxy`(`devices.json`, CA, 규칙)를 같이 쓴다. `devices.json`은 옛 앱이 읽을 수 있는 모양이어야 한다(§4.3.3).
- **설정과 세션 파일**
  - UserDefaults는 Debug와 릴리스가 따로다(번들 ID가 다르다).
  - 새 키 `eyeproxy.hostGroups`, `eyeproxy.openTabs`, `eyeproxy.restoreTabsAtLaunch`는 없으면 기본값이다.
  - 세션 파일 형식은 바꾸지 않는다.
- **플랫폼과 권한**
  - macOS 15+, Swift 6.
  - 새로 추가하는 기능 중 로컬 네트워크 권한이 필요한 것은 없다. Bonjour 시작 조건은 지금 그대로다.

## 6. 만드는 사람에게 맡기는 것

- New Domain or App 시트의 배치, 고르기 목록의 모양과 정렬.
- 그룹 매칭에 쓰는 미리 컴파일한 매처를 어떻게 만들지. 정규식 하나로 합치거나, 와일드카드 없는 패턴은 집합으로 따로 볼 수 있다. 단, 요청마다 정규식을 새로 만들면 안 된다.
- ARP 표 해석의 세부: 구조체 정렬, `sockaddr_dl`에서 주소를 꺼내는 방식.
- 탭 순서를 얻는 방법: `tabbedWindows`, `NSApp.orderedWindows`.
- 복원한 앞 탭을 앞으로 내는 시점.
- 연결된 기기 행에 MAC과 "이전" 표시를 어떻게 보일지.
