# EyeProxy P1 (보기) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** iOS·tvOS 기기/시뮬레이터와 이 Mac의 HTTP(S) 트래픽을 EyeProxy로 복호화해 보고, 세션으로 저장하는 macOS 앱(P1 "보기" 단계)을 만든다.

**Architecture:** 레포 하나에 로컬 Swift 패키지 둘(`EyeProxyCore` = SwiftNIO 프록시 엔진·TLS MITM, `EyeProxyKit` = 세션·설정·기기·시스템 연동)과 SwiftUI 앱 타깃. 의존은 App → Kit → Core 한 방향. Core는 `AsyncStream<FlowEvent>`로만 바깥과 말하고, Tools는 `RequestInterceptor`/`ResponseInterceptor` 배열로 꽂힌다. HTTPS는 CONNECT 대상 호스트를 보고 리프 인증서를 발급해 MITM 한다(SNI 콜백 불필요).

**Tech Stack:** Swift 6 (strict concurrency), SwiftUI, macOS 15+, swift-nio / swift-nio-ssl / swift-nio-extras, swift-certificates + swift-crypto, JavaScriptCore(P3), Sparkle 2, XcodeGen, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-11-05-eyeproxy-design.md`

## Global Constraints

- macOS 15.0+, Swift 6 strict concurrency, Xcode 16+. 패키지 `swift-tools-version: 6.0`, `platforms: [.macOS(.v15)]`.
- 외부 패키지는 **swift-nio, swift-nio-ssl, swift-nio-extras, swift-certificates, swift-asn1(swift-certificates의 의존성, DER 직렬화용 `SwiftASN1` 모듈), swift-crypto, Sparkle**만. 다른 패키지를 쓰려면 스펙을 고친다.
- UI 문자열은 `EyeProxy/Localizable.xcstrings`(String Catalog)에 두고 개발 언어는 `ko`. 영어 번역은 P2.
- 번들 ID `com.tv.eyeproxy` (Debug `com.tv.eyeproxy.debug`), 제품명 `EyeProxy`, 앱 데이터 디렉터리 `~/Library/Application Support/com.tv.eyeproxy/`.
- 기본 포트 **9090**, CA 배포 호스트 **`eyeproxy`** (`http://eyeproxy/ssl`).
- App Sandbox **끔**. Debug는 팀 `F64BRNFSBB` 자동 서명, Release는 unsigned 빌드 후 `scripts/release.sh` 재서명·공증.
- P1은 HTTP/1.1만(클라이언트·업스트림 모두). h2는 P3.
- Core는 AppKit/SwiftUI/Foundation의 파일시스템을 import하지 않는다(단 `CertificateAuthority.save/load`는 URL을 받되 Foundation `Data` 읽기/쓰기만).
- 동시성: 엔진은 NIO EventLoop, Kit의 `@Observable` 스토어와 앱은 `@MainActor`. 락·세마포어 직접 사용 금지.
- 테스트는 Swift Testing(`import Testing`). 실행: `swift test --package-path Packages/<pkg>`.
- 커밋 메시지: `<type>(<scope>): <한국어 요약>` (예: `feat(core): 인터셉터 체인 추가`). Co-Authored-By 꼬리는 세션 지침대로.

## Review Focus

1. **포트 9090이 이미 사용 중**(Proxyman이 켜져 있음): 앱이 죽지 않고 "포트 9090 사용 중 — Proxyman을 끄거나 설정에서 포트를 바꾸세요"를 띄워야 한다. → Task 5 `start()`가 `ProxyServerError.portInUse(Int)`를 던지는 테스트.
2. **비정상 종료 후 시스템 프록시 잔존**: Mac 네트워크가 먹통이 되면 안 된다. 다음 실행 시 백업 파일이 남아 있으면 복원을 제안한다. → Task 12 `SystemProxy.pendingRestore()` 테스트.
3. **SSL 목록에 없는 호스트의 HTTPS**는 복호화 없이 터널로 그대로 통과해야 하고, Flow 목록에는 `CONNECT host:443` 한 줄로만 보인다(기기 앱이 깨지면 안 된다). → Task 6 터널 테스트.
4. **기기가 CA를 신뢰하지 않음**(-9813 계열): 핸드셰이크 실패가 기기 IP·호스트와 함께 Connection Log에 사람 말로 남아야 한다("기기가 EyeProxy 인증서를 신뢰하지 않습니다 — 인증서 신뢰 설정을 확인"). → Task 7 핸드셰이크 실패 테스트.
5. **압축·비텍스트 바디**: `Content-Encoding: gzip/br` 응답은 뷰어에서 풀어서 보여주되 원본 바이트는 보존하고, UTF-8이 아닌 바디는 Raw(hex)로 떨어진다. → Task 10 `BodyDecoder` 테스트.

## 라이브러리 API 메모

(2026-11-05 소스 clone + Swift 6 빌드로 확인한 시그니처. swift-certificates 1.21.1, swift-nio-ssl 2.37.6 기준. 구현자는 이 섹션을 먼저 쓰고, 컴파일이 안 되면 해당 패키지 DocC를 본다. ⚠️는 미검증.)

**swift-certificates** (`import X509, SwiftASN1, Crypto`) — 아래 코드는 컴파일·실행 확인됨.
```swift
let caKey = P256.Signing.PrivateKey()
let caName = try DistinguishedName { CommonName("EyeProxy Root CA"); OrganizationName("EyeProxy") }
let caCert = try Certificate(
  version: .v3, serialNumber: Certificate.SerialNumber(), publicKey: .init(caKey.publicKey),
  notValidBefore: now.addingTimeInterval(-3600), notValidAfter: now.addingTimeInterval(3650*86400),
  issuer: caName, subject: caName,
  extensions: try Certificate.Extensions {
    Critical(BasicConstraints.isCertificateAuthority(maxPathLength: 0))
    Critical(KeyUsage(keyCertSign: true, cRLSign: true))
    SubjectKeyIdentifier(hash: Certificate.PublicKey(caKey.publicKey))
  },
  issuerPrivateKey: .init(caKey))
let leafCert = try Certificate(
  version: .v3, serialNumber: Certificate.SerialNumber(), publicKey: .init(leafKey.publicKey),
  notValidBefore: now.addingTimeInterval(-3600), notValidAfter: now.addingTimeInterval(397*86400),  // iOS/macOS 신뢰 제약: 398일 이하
  issuer: caCert.subject, subject: try DistinguishedName { CommonName(host) },
  extensions: try Certificate.Extensions {
    Critical(BasicConstraints.notCertificateAuthority)
    Critical(KeyUsage(digitalSignature: true))
    try ExtendedKeyUsage([.serverAuth])
    SubjectAlternativeNames([.dnsName(host)])      // IP면 .ipAddress(ASN1OctetString(...)) ⚠️
  },
  issuerPrivateKey: .init(caKey))
let pem = try leafCert.serializeAsPEM().pemString          // PEMSerializable (SwiftASN1)
var ser = DER.Serializer(); try ser.serialize(leafCert); let der = ser.serializedBytes   // DER는 SwiftASN1
let keyPEM = try Certificate.PrivateKey(leafKey).serializeAsPEM().pemString   // PKCS#8. (pemRepresentation 프로퍼티는 없음)
let back = try Certificate(pemEncoded: pem); let keyBack = try Certificate.PrivateKey(pemEncoded: keyPEM)
```

**swift-nio-ssl** (`import NIOSSL`) — 컴파일 확인.
```swift
let chain = try [NIOSSLCertificate(bytes: Array(pem.utf8), format: .pem)]
let key   = try NIOSSLPrivateKey(bytes: Array(keyPEM.utf8), format: .pem)
var sc = TLSConfiguration.makeServerConfiguration(certificateChain: chain.map { .certificate($0) }, privateKey: .privateKey(key))
sc.applicationProtocols = ["http/1.1"]
let serverCtx = try NIOSSLContext(configuration: sc)
NIOSSLServerHandler(context: serverCtx)                                  // non-throwing
var cc = TLSConfiguration.makeClientConfiguration()                      // 업스트림: 기본값(시스템 신뢰). 테스트: cc.trustRoots = .certificates([caNIOCert]); cc.certificateVerification = .noHostnameVerification
try NIOSSLClientHandler(context: try NIOSSLContext(configuration: cc), serverHostname: host)   // throws
```
SNI 콜백 `TLSConfiguration.sslContextCallback`이 있지만 **쓰지 않는다**. CONNECT 대상 호스트로 컨텍스트를 만들어 캐시하는 쪽이 단순하고 SNI 없는 클라이언트에도 안전하다.

**swift-nio HTTP/1** (`import NIOCore, NIOPosix, NIOHTTP1`) — 소스 확인.
- 클라이언트 채널 파이프라인은 `configureHTTPServerPipeline`을 **쓰지 않고** 공식 예제 `swift-nio-examples/connect-proxy`처럼 수동으로: `ByteToMessageHandler(HTTPRequestDecoder(leftOverBytesStrategy: .forwardBytes))` + `HTTPResponseEncoder()` + `ProxyConnectionHandler`. `.forwardBytes`가 핵심: CONNECT 후 디코더를 제거할 때 이미 읽힌 TLS ClientHello 바이트가 다음 핸들러로 넘어간다.
- CONNECT 흐름(예제 `ConnectHandler.swift`): `head.method == .CONNECT` → 업스트림 연결 → `HTTPResponseHead(version: .http1_1, status: .ok, headers: ["Content-Length": "0"])` + `.end(nil)` 쓰기 → `context.pipeline.syncOperations.removeHandler(...)`로 디코더·인코더 제거 → (터널) `GlueHandler.matchedPair()` 양쪽에 추가 후 자기 자신 제거 / (MITM) `NIOSSLServerHandler` 추가 후 디코더·인코더·새 `ProxyConnectionHandler(tlsOrigin:)`를 다시 추가. ⚠️ MITM 조합의 실제 동작은 미검증 → Task 7 테스트가 검증.
- 업스트림: `ClientBootstrap` + (`NIOSSLClientHandler`) + `addHTTPClientHandlers()`. 파트 타입: `HTTPClientRequestPart = HTTPPart<HTTPRequestHead, IOData>`, `HTTPClientResponsePart = HTTPPart<HTTPResponseHead, ByteBuffer>`, 케이스 `.head/.body/.end(HTTPHeaders?)`.

**구성 프로파일 키** (developer.apple.com/documentation/devicemanagement) — Wi-Fi·TopLevel 확인, 루트 인증서는 ⚠️ 일반 지식.
- TopLevel: `PayloadType="Configuration"`, `PayloadIdentifier`, `PayloadUUID`, `PayloadVersion=1`, `PayloadContent=[dict]`, 선택 `PayloadDisplayName`, `PayloadOrganization`.
- `com.apple.wifi.managed`: `SSID_STR`, `EncryptionType` ∈ `WEP|WPA|WPA2|WPA3|Any|None`, `Password`, `AutoJoin`(bool), `ProxyType` ∈ `None|Manual|Auto`, `ProxyServer`, `ProxyServerPort`(int). 각 payload dict에도 `PayloadType/PayloadVersion/PayloadIdentifier/PayloadUUID/PayloadDisplayName`.
- `com.apple.security.root`: `PayloadContent` = DER `Data`, 선택 `PayloadCertificateFileName`.

**macOS CLI** — 로컬 `-help`로 확인.
- `networksetup -listallnetworkservices`(첫 줄은 안내 문구, `*` 접두는 비활성), `-getwebproxy <svc>`, `-setwebproxy <svc> <host> <port>`, `-setsecurewebproxy`, `-setwebproxystate <svc> on|off`, `-setsecurewebproxystate`, `-setproxybypassdomains <svc> <d1> [d2…]`. ⚠️ 변경 시 관리자 인증 필요 여부 미확인 → Task 12의 `PrivilegedShell` 재시도로 흡수.
- `security add-trusted-cert [-d] [-r trustRoot] [-k keychain] certFile` — `-d`는 admin 신뢰 도메인(시스템). 사용자 도메인은 `-k ~/Library/Keychains/login.keychain-db`. ⚠️ 권한 프롬프트 여부 미확인.
- `xcrun simctl keychain <udid> add-root-cert <path>`; `xcrun simctl list devices booted -j` → `{"devices": {"com.apple.CoreSimulator.SimRuntime.tvOS-18-1": [{"udid","name","state":"Booted",…}]}}` (빈 런타임 배열 허용).
